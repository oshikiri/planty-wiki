# 実装範囲とタスクリスト

初期版には、オンラインのローカル利用とPhase 4のオフライン対応を含める。
Cloud Syncの実現可能性はPhase 2とPhase 3で先行検証し、Phase 4のオフライン対応と並行して進める。Phase 5はPhase 3とPhase 4の完了後に開始する。

Cloud Syncの対象と設計方針は [[Cloud Sync]]、API契約とD1スキーマは [[Cloud Sync API]] に記載する。

完了した Phase は削除する。

## Phase 2: Cloud Sync基盤の実現可能性検証

ChatGPT Sitesの認証・同期API・D1を第一候補として、Siteのアクセス設定で許可された利用者が共有するCloud Syncの外部基盤を検証する。

### 実サイトのスモーク検証

`probe` をSites上へ配置し、認証、D1接続、フロントエンドからのAPI呼び出し、現行アプリに必要なブラウザー機能を検証する。同期用のD1スキーマとノート操作APIはPhase 3で配置する。

- [ ] Sites上で保存した検証用バージョンへ `probe` とD1バインディングを配置する。
- [ ] Siteのアクセス設定で許可された利用者だけがSiteと同期APIへアクセスでき、未認証や認証ヘッダーの偽装では利用できないことを確認する。
- [ ] 認証済みの `probe` がAPI契約どおり応答し、D1へ接続できることを確認する。
- [ ] Siteのアクセス設定で許可した2つの利用者が、2つのブラウザーから `probe` を利用できることを確認する。
- [ ] フロントエンドから同一オリジンのAPIを呼び出せることを確認する。
- [ ] OPFS、Worker、SharedArrayBuffer、Cross-Origin IsolationがSites上で動作することを確認する。

### 完了条件

- [ ] Sites上で認証付きAPIとD1接続を確認できている。
- [ ] 2つのブラウザーから同じSiteのAPIを利用できている。
- [ ] 現行アプリを動かすためのブラウザー機能がSites上で利用できている。

## Phase 3: Cloud Sync垂直スライス検証

Phase 2で基盤が利用可能と判断できた場合に、1Site・1ノートの最小構成で同期処理を検証する。

- [ ] 同じSiteの2つのクライアント間で、1件のノートをアップロード・ダウンロードできるようにする。
- [ ] Site全体で単調増加する変更連番を発行し、更新と削除を変更ログへ記録する。
- [ ] 前回の変更連番以降の変更をページング取得し、ローカルカーソルを更新できるようにする。
- [ ] ローカル保存と送信待ち記録を同一トランザクションで保持できることを確認する。
- [ ] 同期失敗時に送信待ちを保持し、再送できることを確認する。
- [ ] 同じ操作IDによる再送をAPI契約どおり冪等に処理できることを確認する。
- [ ] 版番号の不一致を競合として検出し、サーバー版とローカル版を保持できることを確認する。
- [ ] 削除を変更ログへ記録し、差分同期できることを確認する。
- [ ] 入力と保存量の上限を決定し、上限到達時に部分的な保存を行わないことを確認する。
- [ ] 暫定的に、最後にサーバーが受理した更新を最新版本文として採用する。
- [ ] 同期できない場合にローカル編集を保持できることを確認する。
- [ ] 検証結果、採用する構成、未解決の制約を文書化する。

### 完了条件

- [ ] 同じSiteの2つのクライアントで、1件のノートの保存と取得を検証できている。
- [ ] 更新と削除を含む差分同期と、変更連番のカーソル更新を検証できている。
- [ ] 再送の冪等性、競合検出、暫定的な最新版採用、ローカルデータ保持を検証できている。
- [ ] Phase 4のオフライン対応とPhase 5の本実装に必要な変更点が整理できている。

## Phase 4: オフライン対応

初回オンライン起動後に、オフラインでもローカルノートを利用できる状態にする。

- [ ] 初回起動時に必要なアプリケーションリソースを取得する。
- [ ] 初回起動が正常に完了した後、必要最小限のリソースをキャッシュする。
- [ ] オフラインでアプリケーションを起動できるようにする。
- [ ] オフラインでローカルのノート機能を利用できるようにする。

### 完了条件

- [ ] 初回オンライン起動後、ネットワークを切断してもアプリケーションを起動できる。
- [ ] オフライン状態で保存済みのノートを編集・保存できる。

## Phase 5: Cloud Sync本実装

Phase 2とPhase 3で実現可能と判断した構成を使い、Phase 4の完了後に複数端末で利用できる同期機能を実装する。

- [ ] Siteのアクセス設定で許可された利用者だけが利用できる認証とアクセス制御を追加する。
- [ ] ローカルデータをCloud Syncの保存先へ同期する。
- [ ] 複数端末間で複数のノートを同期する。
- [ ] ノートの削除を同期する。
- [ ] 同時編集や更新競合を検出する。
- [ ] 競合したノートを利用者が解決できるようにする。
- [ ] 履歴からノートを復元できるようにする。
- [ ] フォルダーインポート時の競合を解決できるようにする。
- [ ] 同期状態と競合を表示するUIを提供する。
- [ ] ネットワーク障害時にローカル編集を失わず、再接続後に同期できるようにする。

### 完了条件

- [ ] Siteのアクセス設定で許可された利用者が認証済みの複数端末から同じノートを利用できる。
- [ ] 同期失敗時にローカルデータが失われない。
- [ ] 競合発生時に一方の編集結果を無言で上書きしない。

## Phase 6: 非機能改善

データ量と処理時間が増えた場合でも、アプリケーションを安定して利用できるようにする。

- [ ] 件数が増えたとき、全件スキャンやDOM全描画を避ける。
- [ ] 必要に応じて仮想リストやSQLiteインデックスを導入する。
- [ ] ディレクトリインポートやワーカー越しのストレージ操作に並列数、深さ、件数の上限を設ける。
- [ ] 長時間処理をキャンセルできるようにする。
- [ ] 長時間処理でブラウザーのメインスレッドをブロックしない。

## Phase 7: 拡張機能

ファイル機能とアプリケーションのインストール機能を実装する。

- [ ] 画像をノートで扱えるようにする。
- [ ] 添付ファイルをノートで扱えるようにする。
- [ ] アプリ全体のインストール機能を提供する。
