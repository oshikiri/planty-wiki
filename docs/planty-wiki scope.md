# 実装範囲とタスクリスト

Phase 1とPhase 4を初期版の範囲とする。
Cloud Syncの実現可能性は、Phase 1の公開準備後にPhase 4の完了を待たず、Phase 2とPhase 3として先行検証する。
Phase 2とPhase 3の検証結果をもとに、Phase 5以降の実装方針を判断する。

完了した Phase は削除する。

## Phase 1: オンラインのローカル版と公開準備

オンライン環境でローカルノートを利用でき、ChatGPT Sitesへ公開できる状態にする。

- [ ] ChatGPT Sitesへホスティングできる状態にする。

### 完了条件

- [ ] ChatGPT Sitesで初期版を公開し、オンラインで利用できる。

## Phase 2: Cloud Sync基盤の実現可能性検証

ChatGPT Sitesの認証・同期API・D1を第一候補として、Cloud Syncの外部基盤を検証する。

- [ ] ChatGPT Sitesの認証から、認証済み利用者を同期APIで識別できることを確認する。
- [ ] ChatGPT Sites上に同期APIとD1を配置できることを確認する。
- [ ] フロントエンドから認証付きで同期APIを呼び出せることを確認する。
- [ ] 利用者ごとに同期データを分離できることを確認する。
- [ ] 現在のローカルデータモデルをCloud Syncへ適用できるか確認する。
- [ ] API、認証、D1の制約と運用上の前提を文書化する。

### 完了条件

- [ ] ChatGPT Sitesの認証、同期API、D1を使う構成の可否が判断できている。
- [ ] 利用者識別、認証付きAPI呼び出し、データ分離を検証できている。
- [ ] 実現不可能な制約がある場合に、代替案または中止条件が決まっている。

## Phase 3: Cloud Sync垂直スライス検証

Phase 2で基盤が利用可能と判断できた場合に、1利用者・1ノートの最小構成で同期処理を検証する。

- [ ] 同一利用者の2つのクライアント間で、1件のノートをアップロード・ダウンロードできるようにする。
- [ ] ローカル保存と送信待ち記録を同一トランザクションで保持できることを確認する。
- [ ] 同期失敗時に送信待ちを保持し、再送できることを確認する。
- [ ] 同じ操作IDで再送しても、サーバー側で二重適用されないことを確認する。
- [ ] 版番号の不一致を検出し、検証用に競合として記録する。
- [ ] 暫定的に、最後にサーバーが受理した更新を最新版本文として採用する。
- [ ] 同期できない場合にローカル編集を保持できることを確認する。
- [ ] 検証結果、採用する構成、未解決の制約を文書化する。

### 完了条件

- [ ] 同一利用者の2つのクライアントで、1件のノートの保存と取得を検証できている。
- [ ] 再送、重複防止、競合検出、暫定的な最新版採用、ローカルデータ保持を検証できている。
- [ ] Phase 4のオフライン対応とPhase 5の本実装に必要な変更点が整理できている。

## Phase 4: オフライン対応

初回オンライン起動後に、オフラインでもローカルノートを利用できる状態にする。

- [ ] 初回起動時に必要なアプリケーションリソースを取得する。
- [ ] 初回起動が正常に完了した後、必要最小限のリソースをキャッシュする。
- [ ] オフラインでアプリケーションを起動できるようにする。
- [ ] オフラインでローカルのノート機能を利用できるようにする。

### 完了条件

- [ ] 初回オンライン起動後、ネットワークを切断してもアプリケーションを起動できる。
- [ ] オフライン状態で保存済みのノートを編集・保存できる。

## Phase 5: Cloud Sync本実装

Phase 2とPhase 3の検証で実現可能と判断した構成を使い、複数端末で利用できる同期機能を実装する。

- [ ] 認証とアクセス制御を追加する。
- [ ] ローカルデータをCloud Syncの保存先へ同期する。
- [ ] 複数端末間で複数のノートを同期する。
- [ ] ノートの削除を同期する。
- [ ] 同時編集や更新競合を検出する。
- [ ] 競合したノートを利用者が解決できるようにする。
- [ ] 履歴からノートを復元できるようにする。
- [ ] フォルダーインポート時の競合を解決できるようにする。
- [ ] 同期状態と競合を表示するUIを提供する。
- [ ] ネットワーク障害時にローカル編集を失わず、再接続後に同期できるようにする。

### 完了条件

- [ ] 利用者が認証済みの複数端末から同じノートを利用できる。
- [ ] 同期失敗時にローカルデータが失われない。
- [ ] 競合発生時に一方の編集結果を無言で上書きしない。

## Phase 6: 非機能改善

データ量と処理時間が増えた場合でも、アプリケーションを安定して利用できるようにする。

- [ ] 件数が増えたとき、全件スキャンやDOM全描画を避ける。
- [ ] 必要に応じて仮想リストやSQLiteインデックスを導入する。
- [ ] ディレクトリインポートやワーカー越しのストレージ操作に並列数、深さ、件数の上限を設ける。
- [ ] 長時間処理をキャンセルできるようにする。
- [ ] 長時間処理でブラウザーのメインスレッドをブロックしない。

## Phase 7: 拡張機能

ファイル機能とアプリケーションのインストール機能を実装する。

- [ ] 画像をノートで扱えるようにする。
- [ ] 添付ファイルをノートで扱えるようにする。
- [ ] アプリ全体のインストール機能を提供する。
