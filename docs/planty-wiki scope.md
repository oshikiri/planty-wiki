# 実装範囲とタスクリスト

初期版には、オンラインのローカル利用とPhase 4のオフライン対応を含める。
Cloud Syncの基盤の実現可能性はPhase 2で確認した。Phase 3では、まず同じSiteを2台のクライアントで利用できる最小の垂直スライスを検証する。詳細な認証境界、差分同期、失敗回復、競合処理は後続へ回す。Phase 5はPhase 3とPhase 4の完了後に開始する。

Cloud Syncの対象と設計方針は [[Cloud Sync]]、API契約とD1スキーマは [[Cloud Sync API]] に記載する。

完了した Phase は削除する。

## Phase 3: Cloud Sync垂直スライス検証

Phase 2で基盤の基本動作を確認した。Phase 3では、同じSiteを2台のクライアントで利用し、1Site・1ノートの最小構成による同期処理を検証する。

- [x] 同じSiteを2台のクライアントで開き、両方から同期APIを利用できることを確認する。
- [x] 1台目で1件のノートを保存し、2台目でそのノートを取得できることを確認する。
- [x] 2台目で同じノートを更新し、1台目で更新結果を取得できることを確認する。
- [x] 検証結果、採用する構成、未解決の制約を文書化する。

### 完了条件

- [x] 同じSiteの2つのクライアントで、1件のノートを双方向に保存・取得できている。
- [x] Phase 4のオフライン対応とPhase 5の本実装に必要な変更点が整理できている。

## Phase 4: オフライン対応

初回オンライン起動後に、オフラインでもローカルノートを利用できる状態にする。

- [x] 初回起動時に必要なアプリケーションリソースを取得する。
- [x] 初回起動が正常に完了した後、必要最小限のリソースをキャッシュする。
- [x] オフラインでアプリケーションを起動できるようにする。
- [x] オフラインでローカルのノート機能を利用できるようにする。

### 完了条件

- [x] 初回オンライン起動後、ネットワークを切断してもアプリケーションを起動できる。
- [x] オフライン状態で保存済みのノートを編集・保存できる。

## Phase 5: Cloud Sync本実装

Phase 3とPhase 4で実現可能と判断した構成を使い、最低限のCloud Syncを複数端末で利用できる状態にする。同期の堅牢化と高度な管理機能はPhase 6へ回す。

クライアント側では、ローカル保存と送信待ち記録を同じトランザクションで保持し、ノートの保存・削除後とノート一覧の読み込み時にバックグラウンド同期を開始する処理を実装した。同期処理は送信待ち変更の送信、変更連番による差分取得、複数ノートの反映、削除の反映に対応する。前回の同一Site・複数クライアントによる検証結果を、このPhaseの同一利用者検証の証跡として採用する。検証記録は [[Cloud Sync Phase 3.local]] に保存している。別の利用者を使った認可検証は、このPhaseの対象外とする。

- [x] Siteのアクセス設定で許可された利用者だけが利用できる認証とアクセス制御を追加する。
- [x] 同じ利用者が複数のブラウザー・端末から同じSiteを利用できることを確認する。
- [x] ローカルデータをCloud Syncの保存先へ同期する。
- [x] 複数端末間で複数のノートを同期する。
- [x] ノートの削除を同期する。

### 完了条件

- [x] 同じ利用者が認証済みの複数端末から同じノートを利用できる。
- [x] Phase 6の堅牢化に必要な変更点が整理できている。

## Phase 6: Cloud Sync堅牢化と非機能改善

Phase 5の最小構成を土台にして、同期の失敗回復、競合処理、制約、性能を改善する。必要な変更点は [[Cloud Sync Phase 6]] に整理した。

- [x] Site全体で単調増加する変更連番を発行し、更新と削除を変更ログへ記録する。
- [x] 前回の変更連番以降の変更をページング取得し、ローカルカーソルを更新できるようにする。
- [x] ローカル保存と送信待ち記録を同一トランザクションで保持できることを確認する。
- [x] 同期失敗時に送信待ちを保持し、再送できることを確認する。
- [x] 同じ操作IDによる再送をAPI契約どおり冪等に処理できることを確認する。
- [ ] 版番号の不一致を競合として検出し、サーバー版とローカル版を保持できることを確認する。
- [ ] 暫定的に、最後にサーバーが受理した更新を最新版本文として採用する。
- [ ] 入力と保存量の上限を決定し、上限到達時に部分的な保存を行わないことを確認する。
- [ ] 同時編集や更新競合を検出する。
- [ ] 競合したノートを利用者が解決できるようにする。
- [ ] 履歴からノートを復元できるようにする。
- [ ] フォルダーインポート時の競合を解決できるようにする。
- [ ] 同期状態と競合を表示するUIを提供する。
- [ ] 同期できない場合にローカル編集を保持できることを確認する。
- [ ] ネットワーク障害時にローカル編集を失わず、再接続後に同期できるようにする。

- [ ] 件数が増えたとき、全件スキャンやDOM全描画を避ける。
- [ ] 必要に応じて仮想リストやSQLiteインデックスを導入する。
- [ ] ディレクトリインポートやワーカー越しのストレージ操作に並列数、深さ、件数の上限を設ける。
- [ ] 長時間処理をキャンセルできるようにする。
- [ ] 長時間処理でブラウザーのメインスレッドをブロックしない。
