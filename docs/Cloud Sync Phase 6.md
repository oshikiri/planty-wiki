# Cloud Sync Phase 6

## Phase 6に必要な変更点

Phase 5の実装には、同期の基本経路と送信待ちの再送処理がある。Phase 6では、データ損失を防ぐ変更を先に実装する。競合解決と履歴を次に実装し、件数増加に伴う性能改善は必要性を確認してから実装する。

| 領域 | Phase 5の状態 | Phase 6の変更と残課題 |
| --- | --- | --- |
| 競合の保持 | APIは`409 Conflict`とサーバー版を返し、Workerは競合結果を返す。ただし、ローカル版とサーバー版を永続化していない。 | `sync_conflicts`ローカルテーブルを追加し、ローカル操作、サーバー版、編集元の版番号を保存する。競合した送信待ちは再送ループから外し、サイドバーの解決操作まで保持する。解決待ちの再編集はローカル版へ反映し、解決前は再送しない。 |
| 版の更新 | `baseVersion`による楽観的同時実行制御がある。古い版を自動的に上書きしない。 | 利用者が選択または統合した本文を、サーバー版を`baseVersion`とする新しい操作として保存する。「最後にサーバーが受理した更新を採用する」は、無条件の自動上書きではなく、競合解決後の暫定方針として定義する。パス競合は別のパスへの保存または確認後のローカル版破棄で解決する。適用に失敗した競合は保持する。 |
| 入力と保存量の上限 | Workerにはパス、タイトル、本文の上限があるが、APIの入力検証と同じ定数で管理されていない。 | パス512文字、タイトル1024文字、本文50000文字に統一した。超過時は`400`を返し、APIの保存・変更ログ・送信待ちを作成しないことをテストする。Workerとディレクトリインポートでも同じ上限を検証する。 |
| 履歴と復元 | サーバーの変更ログは残るが、履歴を表示・復元するAPIとUIがない。 | ノート単位の履歴取得を追加し、復元内容を新しい版として保存する。既存の変更ログは削除しない。 |
| 同期状態UI | サイドバーには認証状態だけを表示し、送信待ち、失敗、競合を表示していない。 | サイドバーに競合を表示し、最新の保存済みローカル版またはサーバー版を選択できるようにする。選択結果を表示中の本文と一覧へ反映し、保存中と解決中は操作を制御する。認証状態は既存のアクセス表示を使い、失敗と再試行はバックグラウンド処理で扱う。 |
| 失敗回復 | 送信待ちはローカルに保持されるが、オンライン復帰、画面復帰、定期同期、指数バックオフの契機が不足している。 | `online`、`visibilitychange`、起動時、保存後、30秒間隔を同期契機にし、1秒から60秒までの指数バックオフを使う。認証切れではすべての同期経路からの送信を停止する。通信復帰、画面復帰、30秒間隔の認証確認で再ログインを検出して同期を再開する。 |
| フォルダーインポート | ディレクトリを再帰的に読み込み、インポート内容をローカルへ保存する。深さ、件数、並列数、キャンセルを制御していない。 | 深さ20、ファイル数1000、1ファイル1MB、合計20MBの上限とAbortControllerによる保存前のキャンセルを追加した。既存変更との競合解決は未対応とする。 |
| 件数と描画性能 | ノート一覧と一部の読み込み処理は全件を対象にし、仮想化やページングを導入していない。リンク検索用のSQLiteインデックスは存在する。 | ノート一覧をページングまたは仮想リストにし、必要なSQLiteインデックスを追加する。長時間のWorker処理はチャンク化し、キャンセル要求を反映する。 |

## 優先順位

表の項目は、次の優先順位で扱う。

- 先行: 競合データの保持、入力と保存量の上限、失敗回復を対応する。
- 次段: 競合解決、同期状態UI、履歴復元、フォルダーインポートの競合を対応する。
- 条件付き: 件数増加に伴う一覧の仮想化、追加インデックス、大量処理のチャンク化・並列化を、計測で必要性を確認してから対応する。

ただし、ディレクトリインポートの深さ・件数・ファイルサイズの上限とキャンセルは、安全策として先に設計する。

実装の主な変更箇所は、`functions/api/sync/validation.ts`、`functions/api/sync/notes/[noteId].ts`、`functions/api/sync/schema.sql`、`public/sqlite-opfs-worker.js`、`src/types/sync.ts`、`src/services/note-service.ts`、同期状態を表示するコンポーネント、`src/storage/file-bridge.ts`である。まず制約と競合データの保存形式を確定し、その後にWorker、API、UI、インポート処理の順で実装する。
