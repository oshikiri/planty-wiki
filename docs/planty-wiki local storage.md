# ローカルデータ管理

## 保存

- ノートはブラウザー内の永続ストレージに保存する。
- ネットワーク接続やCloud Syncを待たずに、ローカル保存の完了を基準として編集結果を画面へ反映する。
- 保存に失敗した場合は、編集中の内容を失わず、利用者へ失敗を通知する。
- 編集中の入力が数秒間止まったときに、自動保存してSQLiteへ変更を反映する。

## インポートとエクスポート

- インポートまたは一括保存の入力レコードは、1件ずつ検証して挿入する。
    - 無効なレコードが見つかった場合はトランザクション全体を失敗させ、無効なデータをDBへ入れない。
- 利用者が選択したローカルディレクトリからMarkdownをインポートできるようにする。
- Markdownフォルダーをインポートするときは、既存のSQLiteデータベースを消去し、インポート内容で上書きする。
- ディレクトリインポートには、深さ20、ファイル数1000、1ファイル1MB、合計20MBの上限を設ける。ファイル読み取り中と保存要求を送る前までキャンセルできる。保存処理が始まったらキャンセル操作を無効にする。
- MarkdownのエクスポートはExportボタンを押したときだけ実行し、通常の自動保存では実行しない。

## 削除

- 削除UIには確認ダイアログまたはUndoバーを表示し、誤操作ですぐにデータを削除しない。

## SQLiteデータ

- データはSQLite WASMの中間テーブルに保存し、通常の操作ではそこから読み書きする。
- Cloud Syncを利用するSiteでは、OPFSのSQLite DBをブラウザーのSite Originに紐づく共有作業領域として扱い、利用者ごとに分離しない。
- ログアウトしてもローカルDBと未送信の変更は削除しない。次にSiteのアクセスを許可された利用者が利用すると、同じSiteの共有データとして扱う。
- Cloud Syncの競合が発生した場合は、送信待ちのローカル操作とサーバー版を`sync_conflicts`へ保存し、利用者が解決するまで保持する。
    - 解決待ちのノートを再編集した場合は、競合に保持するローカル版を更新し、解決前の自動再送を防ぐ。
    - ローカル版を採用する場合は、サーバー版を基準に新しい送信待ちを作成する。サーバー版を採用する場合は、古い送信待ちを取り除く。
    - パス競合では別のパスへ保存できる。確認後にローカル版を破棄することもできる。
    - 解決に失敗した場合は、トランザクションを取り消して競合とノートを保持する。
- Siteのアクセス権を失っても、既存ブラウザーのOPFSデータは自動消去しない。ローカルデータの保護はブラウザーまたは端末へのアクセス権に依存する。
- UIから参照していないDBテーブルやデータ構造は維持せず、不要になった時点で削除して責務をシンプルにする。
